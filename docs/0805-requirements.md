# ShowTalk 产品需求清单（基于 docs/0805.md 十节建议）

> 目标：把「AI 分析工具」升级为「AI 表达教练」。
> 原则：优先做「为何练 → 练什么 → 练完变强」的闭环感，砍掉工程重、留存收益低的项。
> 现状对账：4 种模式、首页选模式、实时字幕、报告、复练对比、指标体系（填充词/模糊/重复/节奏）、能力画像聚合 **已实现**，多数建议是「在其上改交互/补闭环」，而非从零造。

## 二、P0 MVP 需求（本次交付）

### S1 首进表达测评

**目标**：新用户不直接训练，先做一次 3 分钟测评，产出表达画像，作为后续推荐与成长的基线。

**验收标准**：
- [ ] 未测评用户首次进入定位到 /assessment，拒绝直接进入练习。
- [ ] 提供固定测评题（如「介绍最近做的一件有挑战的事」），含 30 秒准备倒计时。
- [ ] 测评走完整套现有指标/评分管线，产出 4 维能力分（结构/逻辑/流畅/说服）。
- [ ] 画像落库（复用 `packages/core/src/profile`），标记 `is_assessment=true`。
- [ ] 测评后生成初始训练计划（指向 S2 的推荐入口）。
- [ ] 已测评用户跳过此流程，直接进首页。

**实现提示**：测评复用现有 Practice/Review 会话，仅新增一个 `assessment` 会话类型与首访路由守卫；画像已能聚合，只需持久化基线。

---

### S2 首页隐藏复杂度 → AI 推荐今日训练

**目标**：首页不展示 4 个模式，改为「今天提升什么 + AI 推荐 + 开始训练」，把选择成本从用户身上拿走。

**验收标准**：
- [ ] 首页主区改为「今日训练」卡片：展示推荐模式、推荐理由（命中哪个短板）、预估时长。
- [ ] 推荐逻辑：基于测评基线 + 最近一次会话的最弱维度，选一个模式 + 一个针对性题目。
- [ ] 提供「推荐」的切换/刷新（换一题），但默认一键开始，无需理解模式。
- [ ] 4 种模式入口收进次级「模式库」页（高级用户可进入，默认隐藏）。
- [ ] 无推荐依据时（老数据缺失）回退到默认 free 模式。

**实现提示**：新增 `recommendation` 服务（在 `packages/core` 或 `packages/llm`），返回 `{mode, topic, reason, duration}`；首页从「模式 Card 列表」改为单卡片。

---

### S3 AI 教练对话（报告 → 追问）

**目标**：报告不再单向罗列问题，而是以对话方式追问，直到用户形成完整表达。

**验收标准**：
- [ ] 报告页新增「教练对话」区：AI 先给 1 个主改进点，再用选择式追问（A/B/C 或多个原因）引导补充。
- [ ] 追问有结束条件：用户完成一次完整表达（观点+理由+案例）即收束，不做无限循环。
- [ ] 追问结果可一键进入 S6 的「重新表达」。
- [ ] 对话内容走现有 LLM 管线（`packages/llm`），结构化输出选项，前端渲染为可点按钮。

**实现提示**：复用 `feynman.ts` 的追问思路，做成通用教练追问能力；新增 `coachTurn` LLM 函数 + 对话状态持久化。

---

### S6 原话 vs 优化版 + 重录直连

**目标**：将现有「复练对比（指标 delta）」升级为「原话 → AI 改写 → 录制新版 → 前后对比」的直观闭环。

**验收标准**：
- [ ] 报告/复练页展示「你的原话」+「AI 优化版」并排对照（改写版给出改写理由）。
- [ ] 提供「重新表达 / 录制新版」按钮，直接进入同题录音（复用 RetryPage）。
- [ ] 第二次与第一次的对比保留指标 delta，并叠加文案级「原话 vs 优化版」高亮（已有 `buildComparisonHighlights`）。
- [ ] 形成「一次 → 指导 → 二次」记录，写入成长记录（与 S5 共用）。

**实现提示**：`ReviewPage` 已有对比高亮与指标 delta，主要新增 LLM 改写输出 + 重录入口的直连跳转。

## 三、P1 V1.1 需求

### S4 即时反馈（实时提醒）

**目标**：录音过程中实时提示填充词/停滞，扮演「驾校副驾驶」。

**验收标准**：
- [ ] 实时字幕流上叠加提醒（如「其实」已出现 5 次），非打断式、右侧小助手展示。
- [ ] 基于现有 `metrics/filler` 等累积计数触发。
- [ ] 提醒可开关，默认开启，不打断录音。
- [ ] 明确标注为 beta，流式 ASR 下延迟可接受即可。

**实现提示**：工程重（流式 ASR + 低延迟），务必后于 P0 闭环上线；先做「录完即评」的准实时，流式后置。

### S5 游戏化成长系统

**目标**：给长期训练提供反馈感与留存钩子。

**验收标准**：
- [ ] 能力等级：基于画像分累计经验值（Lv + 经验条，4 维分条）。
- [ ] 每日训练完成 + 经验，连续 7 天解锁标记。
- [ ] 经验与等级写入 storage，ProfilePage 展示。
- [ ] 成长记录与 S6 的「一次→二次」记录同源。

### S8 AI 教练人格

**目标**：让 AI 有「人设」，增加留存。

**验收标准**：
- [ ] 教练人格选择（严格 / 鼓励 / 苏格拉底 / 辩论），影响报告与追问的语气与策略。
- [ ] 人格作为 LLM prompt 参数注入，默认「鼓励型」。
- [ ] 设置项持久化，可在 SettingsPage 切换。

## 五、MVP 交付顺序（建议排期）

1. **S1 测评**：新增 assessment 会话 + 首访守卫（复用现有管线，约半天体验量）。
2. **S2 首页推荐**：recommendation 服务 + 首页改造 + 模式库次级页。
3. **S6 改写重录**：ReviewPage 加 LLM 改写 + 重录直连。
4. **S3 教练对话**：coachTurn LLM + 报告页对话区 + 追问收束。
5. 联调「测评 → 推荐 → 训练 → 追问 → 改写重录 → 成长记录」全链路，跑通一次用户旅程。

> 关键：S4 实时反馈**不进入 MVP**，避免拖慢上线；MVP 用「追问 + 前后对比」补足「纠正感」。
